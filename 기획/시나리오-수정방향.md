# 시나리오 수정 방향

[현재 시나리오](시나리오.md) · [소설형 시나리오](시나리오-소설.md) · [토론 기록](../토론기록.md)

## 목적과 기록 방식

사용자님과 대화하며 전체 시나리오의 설정·사건·인물·진행에 관한 수정 방향을 순차적으로 정리합니다.

- 발언 순서에 따라 기록 번호를 부여합니다. 같은 날짜의 대화도 별도 번호로 이어갑니다.
- 사용자님의 말씀을 요약하고, 결정·제안·보류·확인 필요를 구분합니다.
- AI가 덧붙인 아이디어와 해석은 사용자님의 의견과 분리합니다.
- 영향을 받는 기존 설정·월드·문서를 함께 적습니다. 불명확한 영향은 추정으로 표시합니다.
- 이전 의견을 변경하면 기존 기록을 지우지 않고 변경한 기록 번호와 이유를 남깁니다.
- 이 문서에 기록하는 것과 실제 시나리오에 적용하는 것은 구분합니다. 원문 반영은 사용자님의 수정 지시에 따라 수행합니다.

## 순차 기록

### 001 — 수정 방향 논의 시작

- 날짜: 2026-10-13.
- 사용자님의 말씀: 시나리오를 전반적으로 고치려 하며, 설정에 관한 생각을 대화로 나누고 이 문서에 순차적으로 기록하기를 요청하셨습니다.
- 결정: 앞으로의 시나리오 수정 논의를 이 문서에서 관리합니다.
- 구체적인 변경 설정: 아직 전달받지 않았습니다.
- 원문 반영 상태: 시나리오 본문과 월드별 상세안·소설은 아직 수정하지 않았습니다.

### 002 — 인트로와 첫 만남: 봄맞이축제 준비

- 날짜: 2026-10-13.
- 상태: 사용자님이 제시한 시작 이야기와 이후 이야기 정리의 기준입니다. 구체적인 수식어·추가 연출은 미정입니다.
- 범위: 인트로 → 이름 입력 → 고드래곤과 첫 만남 → 나래의 등장·임무 설명 → 1-1 스테이지 선택 화면.

#### 사용자님이 제시한 인트로

> 오래 전부터 여러 종족의 주민들이 함께 살아온 고디월드에, 최근 AI라는 새로운 기술이 등장했습니다. 당신은 고디월드 왕국지원단 일꾼으로서 고드래곤과 함께 주어진 업무를 완수해 나가야 합니다.
>
> 당신의 이름을 알려주세요: ____________

기존 결정인 이름 7자 이내 제한을 유지합니다. 인트로에서 이름을 입력한 뒤 첫 대화에 사용합니다.

#### 고드래곤과의 만남 — 사용자 대사

- 고드래곤: “안녕? 네가 바로 OOO로 유명한 _________ 이구나? 반가워 난 고드래곤이라고 해. 줄여서 고디라고 불러도 좋아.”
- 나: “내가 OOO로 유명하다고? 난 금시초문인데?”
- 고디: “알아알아 뭘 부끄러워하고 그래~”
- 나: “아니 정말...”

`OOO`는 랜덤 수식어, 빈칸은 사용자 이름입니다. 수식어는 유머 장치이며 실제 사용자 평가나 이력으로 취급하지 않습니다. 같은 대화에서 주인공이 되묻는 수식어는 처음 선택한 값과 같아야 합니다. 수식어 목록·선정 방식·저장 범위는 미정입니다.

#### 나래의 등장 — 사용자 대사와 연출

주인공의 말을 끊으며 나래가 갑자기 등장합니다.

- 나래: “거기 고드래곤! 그리고 OO! 한가하게 수다 떨 시간이 없어요! 축제까지 시간이 얼마 남지 않았다고요!”
- 나래: “자 두 분은 이제 한 팀으로 움직이는 거예요! 그러니까 사이좋게 지내요! 그리고 할 일이 뭔지는 이미 들었죠?”
- 고디&나: “아뇨... 아직 못 들었...”
- 나래: “뭐라고요? 아니 또 누가 일을 엉망으로 한거야! 에휴 할 수 없죠. 바쁘니까 한번만 설명할테니 잘 들어요!”
- 나래: “둘은 이제부터 고디월드의 가장 중요한 행사인 봄맞이축제를 성공시켜야 해요. AI 기술을 활용해서요.”
- 나래: “AI 기술을 잘 모른다는 표정이네요? 걱정하지 마세요! 지금부터 가르쳐줄테니까요!”
- 나&고디: “(정말 활달한 분이네...)”

나래의 `OO`는 사용자 이름을 부르는 자리로 해석합니다. 나래는 친절한 안내인에 더해 활달하고 추진력 있는 행사 진행자의 성격을 갖습니다. 주인공과 고디는 같은 팀이며 AI를 처음부터 잘 아는 인물로 설정하지 않습니다.

#### 이후 이야기의 기준과 영향

- 사용자 역할: 최신 인트로의 사용자 편집을 기준으로 고디월드 왕국지원단 일꾼으로 표기합니다.
- 공통 임무: AI를 활용해 봄맞이축제를 성공시키는 것.
- 동료 이름: 고드래곤, 대화에서는 ‘고디’라는 줄임말 사용 가능.
- 도입 종점: 1-1 스테이지를 선택하는 화면. 1-1의 학습 설명·문제는 다음 이야기에서 정리합니다.
- 기존 시작의 마을 장터 준비 설정과 소설의 임명장 도입은 새 방향에 맞춰 재검토할 대상입니다.
- 월드 2~6의 지역별 사건을 봄맞이축제와 어떻게 연결할지 아직 정하지 않았습니다. 모든 기존 사건을 자동으로 축제 사건으로 확정하지 않습니다.

#### AI 검토 의견 — 사용자 설정과 구분

- 고디의 능청스러운 인사와 나래의 끼어들기로 관계·임무를 자연스럽게 소개할 수 있습니다.
- 나래의 ‘한번만 설명’은 바쁜 성격의 대사로 유지하되 실제 설명 다시 보기·힌트·재도전 기능을 제한하는 규칙으로 적용하지 않는 것을 제안합니다.
- 축제 일정의 긴박함은 이야기 분위기이며 실제 플레이 제한시간을 추가하는 결정은 아닙니다.
- 랜덤 수식어는 ‘간식 위치를 기막히게 찾는’, ‘쉬는 시간을 놓치지 않는’처럼 가벼운 허풍 후보를 제안합니다. 외모·능력의 모욕이나 실제 사용자에 대한 평가로 만들지 않습니다. 후보 목록은 미확정입니다.
- 여러 인물이 동시에 말하는 장면은 이름표·캐릭터 교대 등 대화화면 구현 방법을 추후 정합니다.

- 원문 반영 상태: 이 문서에 기록했습니다. 전체·월드별 시나리오와 소설 원문은 아직 수정하지 않았습니다.

### 003 — 월드 1의 다섯 스테이지 재구성

- 날짜: 2026-10-13.
- 상태: 사용자님이 지정한 구성과 조작을 기록합니다. 설명문·정답·오답 후보·채점 기준은 아직 구체화 전입니다.
- 이야기 연결: 나래가 주인공과 고디에게 AI를 가르칩니다. 봄맞이축제 임무를 준비하는 입문 단계입니다.

#### 1-1 — AI의 개념

- 유형: 드래그 빈칸 채우기.
- AI 개념 설명문에서 중요한 단어 4개를 빈칸으로 표시합니다.
- 문장 아래 후보 단어 8개 중 4개를 골라 정확한 자리에 드래그합니다.
- 설명문·후보 8개·정답 위치는 미정입니다.

#### 1-2 — AI의 기능(분류 / 예측 / 생성) 구분하기

- 유형: 드래그 카드 분류.
- 분류·예측·생성의 세 칸에 아래 작동 사례를 넣습니다.
- 사용자님이 제시한 사례:
  - 문서를 입력하면 문서에 있는 글자를 추출해 줌.
  - 과거 축제의 매출자료를 학습해 다음 달 축제 매출을 예상.
  - 입력받은 축제 내용에 따라 안내문 초안 작성.
  - 그림을 묘사한 문장에 따라 그림 만들기.
- 예측 매출은 예측, 안내문·그림 작성은 생성으로 연결하는 안입니다. 문서 글자 추출을 분류에 넣는 정답은 아직 확정하지 않습니다. 아래 검토 의견을 참고합니다.

#### 1-3 — 대규모 언어모델과 컨텍스트 이해

- 유형: 드래그 빈칸 채우기 2개 활동.
- 첫 활동: 대규모 언어모델 설명문에 빈칸 4개, 후보 단어 8개. 4개를 정확한 위치에 넣습니다.
- 두 번째 활동: 컨텍스트 설명문에 빈칸 4개, 후보 단어 8개. 4개를 정확한 위치에 넣습니다.
- 각 설명문과 후보·정답은 별도로 작성해야 합니다.

#### 1-4 — LLM 대화의 요령

- 유형: 이지선다 3개 질문.
- 사용자님이 제시한 비교:
  1. 핵심 단어 위주로 간결하게 질문 / 관련 내용을 많이 설명.
  2. 바로 답변 받기 / 계획을 먼저 세우고 실행.
  3. 답변 신뢰 / 다시 검증하는 습관.
- 상황과 질문 표현·해설·정답 기준은 구체화 전입니다. 첫 두 질문을 모든 요청에 적용되는 단일 규칙으로 확정하지 않습니다.

#### 1-5 — AI로 해결하기 적합한 문제

- 유형: 사례 선택 + 이유 서술 + 내부 LLM API 채점.
- 사용자님의 학습 의도: 규칙적이고 매뉴얼로 설명할 수 있으며 자주 반복되는 문제의 적합성을 여러 사례로 이해합니다.
- 사례 중 적합한 문제를 고르고, AI로 해결하기 적합한 이유를 직접 설명합니다.
- 내부 API를 채점에 사용하는 방향을 요청하셨습니다. 호출 명세·평가 기준·점수·통과 조건·일관성 검증·실패 처리는 아직 미정입니다.
- 기존 ‘LLM 단일 점수로 판정하지 않음’ 제안과의 관계는 다시 논의합니다. API 채점 도입을 기록하되 API 점수 하나를 무조건 최종 통과 판정으로 사용하는 것으로 추가 해석하지 않습니다.

#### AI전문가 검토 의견 — 사용자 결정과 구분

- 문서 글자 추출은 ‘문자인식·추출’이라는 작업으로 설명하는 것이 명확합니다. 이를 세 기능의 퀴즈에서 단순히 분류로 채점하면 혼동할 수 있습니다. 분류 사례를 ‘축제 관련 문서를 안내·주문·문의로 나누기’로 교체하거나 추출 범주를 추가하는 후보를 제안합니다. 아직 적용하지 않습니다.
- LLM 요청은 단어 수가 아니라 목적에 필요한 맥락을 충분히 전달하는 방향으로 설명하는 안을 제안합니다. 무조건 많은 내용을 넣는 답을 정답으로 만들지 않습니다.
- 계획은 복합 작업에, 바로 답변은 단순 작업에 적합할 수 있도록 상황을 제시하는 질문을 제안합니다. 모든 작업에 계획을 의무화하지 않습니다.
- 반복·규칙·매뉴얼이 명확한 일은 일반 규칙 기반 자동화로도 처리할 수 있습니다. AI 적합성 사례는 글·비정형 자료 해석의 필요성, 자료 준비, 오류 영향과 검토 가능성을 함께 비교하는 안을 제안합니다.
- 드래그를 주요 조작으로 유지하되 클릭·키보드로도 빈칸·분류를 수행하는 대체 조작은 기존 접근성 방향과 연결해 검토합니다.
- API 채점은 선택 사례와 서술 이유를 함께 평가하고, 근거를 인용한 피드백·동등한 표현 허용·응답 실패 재시도·평가 이의 재검토를 설계하는 후보입니다.

- 영향 문서: 월드 1 상세안·교육과 미션·진행 유형·화면·기술과 검증·소설의 첫 장.
- 원문 반영 상태: 수정방향 문서에만 기록했습니다. 기존 월드 1의 상세 활동과 문항은 아직 교체하지 않았습니다. 아래 기록004에서 검토 쟁점의 결정 내용을 이어갑니다.

### 004 — 월드 1 검토 의견 채택

- 날짜: 2026-10-13.
- 사용자님의 결정: 기록003에 대한 AI전문가의 세 가지 보완 의견을 반영하도록 승인하셨습니다.
- 적용 범위: 수정 방향의 정답 설계 기준을 갱신합니다. 기록003의 최초 제안은 변경 이력으로 보존합니다.

#### 1-2 — 문서 분류 사례로 교체

- 최초 사례 ‘문서에 있는 글자를 추출’을 **‘축제 관련 문서를 안내·주문·문의로 나누기’**로 교체합니다.
- 분류 칸: 축제 문서를 안내·주문·문의로 나누기.
- 예측 칸: 과거 축제 매출자료를 학습해 다음 달 축제 매출을 예상.
- 생성 칸: 입력받은 축제 내용에 따라 안내문 초안 작성, 그림을 묘사한 문장에 따라 그림 만들기.
- 글자 추출을 세 기능 중 ‘분류’로 채점하는 안은 사용하지 않습니다.

#### 1-4 — 상황을 명시한 이지선다

- 질문1: 필요한 목적·자료·조건을 생략한 단어 나열과 **작업에 필요한 맥락을 제공한 요청**을 비교합니다. 무조건 많은 내용을 넣는 것을 정답으로 삼지 않습니다.
- 질문2: **여러 단계와 조건이 있는 복합 작업**에서 바로 최종 답을 요청하는 방식과 계획·단계 확인 후 실행하는 방식을 비교합니다. 해당 상황에서는 계획 후 실행을 정답 방향으로 둡니다. 단순 작업까지 계획을 항상 요구하지 않습니다.
- 질문3: 사실·수치 등이 포함된 답변을 그대로 신뢰하는 방식과 **원자료·근거를 다시 확인하는 방식**을 비교합니다.
- 유형은 이지선다3문항을 유지합니다. 실제 문장과 선택지·해설은 다음 단계에서 작성합니다.

#### 1-5 — AI와 일반 자동화의 적합성 비교

- 반복·규칙·매뉴얼이 명확하다는 이유만으로 AI가 반드시 적합하다고 설명하지 않습니다.
- 자연어·비정형 자료를 해석하거나 초안을 만드는 일에서 AI의 도움과 검토 필요성을 살펴봅니다.
- 정해진 합계·명확한 규칙에 따른 반복 처리는 계산 도구·규칙 기반 자동화로 충분한 사례와 비교합니다.
- 사례 선택 후 사용자가 **AI를 선택한 이유 또는 일반 도구가 더 적합한 이유**를 설명합니다. AI를 쓰지 않는 타당한 선택을 오답으로 처리하지 않습니다.
- 내부 LLM API 채점 방향은 유지합니다. 사례 조건과 선택 이유의 관계·근거·한계를 보는 평가 기준을 설계해야 하며 점수·통과·재검토 방식은 미정입니다.

- 반영 상태: 위 세 가지를 이 수정방향 문서의 현행 기준으로 반영했습니다. 월드별 상세안·전체 시나리오·소설 원문은 아직 교체하지 않았습니다.

## 시작 전 — 인트로와 첫 만남

설명문: “오래 전부터 여러 종족의 주민들이 함께 살아온 고디월드에, 최근 AI라는 새로운 기술이 등장했습니다. 당신은 고디월드 왕국지원단 일꾼으로서 고드래곤과 함께 주어진 업무를 완수해 나가야 합니다.”

이름 입력: “당신의 이름을 알려주세요: ____________” — 사용자 지정, 7자 이내. 이후 `{사용자명}`으로 표시합니다. 최소 길이·허용 문자·저장 방식은 미정입니다.

- 고드래곤: “안녕? 네가 바로 {랜덤수식어}로 유명한 {사용자명} 이구나? 반가워 난 고드래곤이라고 해. 줄여서 고디라고 불러도 좋아.”
- 나: “내가 {랜덤수식어}로 유명하다고? 난 금시초문인데?”
- 고디: “알아알아 뭘 부끄러워하고 그래~”
- 나: “아니 정말...”

수식어는 가벼운 허풍이며 같은 장면에서 동일한 값을 사용합니다. 목록·선정·저장 범위는 미정입니다.

나래가 주인공의 말을 끊으며 등장합니다.

- 나래: “거기 고드래곤! 그리고 {사용자명}! 한가하게 수다 떨 시간이 없어요! 축제까지 시간이 얼마 남지 않았다고요!”
- 나래: “자 두 분은 이제 한 팀으로 움직이는 거예요! 그러니까 사이좋게 지내요! 그리고 할 일이 뭔지는 이미 들었죠?”
- 고디&나: “아뇨... 아직 못 들었...”
- 나래: “뭐라고요? 아니 또 누가 일을 엉망으로 한거야! 에휴 할 수 없죠. 바쁘니까 한번만 설명할테니 잘 들어요!”
- 나래: “둘은 이제부터 고디월드의 가장 중요한 행사인 봄맞이축제를 성공시켜야 해요. AI 기술을 활용해서요.”
- 나래: “AI 기술을 잘 모른다는 표정이네요? 걱정하지 마세요! 지금부터 가르쳐줄테니까요!”
- 나&고디: “(정말 활달한 분이네...)”

1-1을 선택하는 화면으로 이동합니다. ‘한번만’은 성격을 보여주는 대사이며 다시 보기를 제한하지 않습니다. 축제의 긴박함을 실제 제한시간으로 적용하지 않습니다.

## 1-1 — AI의 개념

**유형: 드래그 빈칸 채우기**

### 진행 형태

| 항목 | 방식 |
| --- | --- |
| 중심 활동 | AI 개념 설명문의 핵심 단어 완성 |
| 화면·조작 | 설명문 빈칸 4개, 후보 단어 8개, 드래그 배치·수정·확인 |
| 순서 | 짧은 설명·예제 → 후보 선택·배치 → 확인 → 해설·해당 빈칸 수정 |
| 제출 | 네 빈칸에 배치한 단어 |
| AI 사용 | 고정 자료·정답 대조, LLM 호출 없음 |

**상황**: 실전 업무를 시작하기 전에 나래가 AI가 어떤 기술인지 설명합니다.

**추가 대사 초안**:

- 나래: “도구를 쓰기 전에 어떤 기술인지부터 알아볼까요? 설명에 들어갈 단어를 골라 주세요.”
- 고디: “여덟 개를 모두 쓰는 건 아니네. 문장을 끝까지 읽어보자.”

**문제·판정**: 중요한 단어 4개에 빈칸이 있는 하나의 설명문을 제시합니다. 후보 8개 중 정확한 4개를 배치합니다. 설명문 원문·정답 4개·오답 후보 4개는 미정이며 기존 문항을 그대로 재사용하지 않습니다. 선택 전 학습 기회를 제공하고 정답이어도 완성 문장과 이유를 설명합니다.

**해설 설계**: AI를 무조건 정확한 답을 주는 기술이나 생성형 AI만으로 설명하지 않습니다. 빈칸별 의미와 문장 전체의 관계를 풀이합니다. 힌트 초안: “이 단어가 들어갔을 때 문장 전체가 어떤 뜻이 되는지 읽어 보세요.”

## 1-2 — AI의 기능(분류 / 예측 / 생성) 구분하기

**유형: 드래그 카드 분류**

### 진행 형태

| 항목 | 방식 |
| --- | --- |
| 중심 활동 | 작동 사례를 분류·예측·생성에 연결 |
| 화면·조작 | 세 범주 칸, 사례 카드 4개, 드래그·재배치·확인 |
| 순서 | 세 기능 설명·예제 → 카드 배치 → 기능별 해설 → 수정 |
| 제출 | 네 카드의 범주 |
| AI 사용 | 고정 사례와 분류 기준, LLM 호출 없음 |

**상황**: 나래가 축제 업무에서 사용할 수 있는 기능을 소개합니다.

**추가 대사 초안**:

- 나래: “AI라고 해서 전부 같은 일을 하는 건 아니에요. 이 도구들이 무엇을 하는지 살펴보세요.”
- 고디: “안내문을 만드는 것과 매출을 예상하는 건 다르겠네.”

| 제시 카드 | 정답 범주 | 해설 방향 |
| --- | --- | --- |
| 축제 관련 문서를 안내·주문·문의로 나누기 | 분류 | 정해진 범주에 자료를 나눔 |
| 과거 축제 매출자료를 학습해 다음 달 축제 매출을 예상 | 예측 | 과거 자료로 미래 값을 추정하며 실제 값과 다를 수 있음 |
| 입력받은 축제 내용에 따라 안내문 초안 작성 | 생성 | 입력 조건을 바탕으로 새 글을 만듦; 사용 전 검토 필요 |
| 그림을 묘사한 문장에 따라 그림 만들기 | 생성 | 입력 설명을 바탕으로 새 그림을 만듦 |

문서 글자 추출을 단순히 ‘분류’로 채점하지 않습니다. 복합 도구의 모든 기능을 배타적으로 구분하는 문제가 아니라, 카드에 명시된 동작을 구분합니다. 힌트 초안: “범주를 나누나요, 앞으로의 값을 예상하나요, 새 내용을 만드나요?”

## 1-3 — 대규모 언어모델과 컨텍스트 이해

**유형: 드래그 빈칸 채우기(두 활동)**

### 진행 형태

| 항목 | 방식 |
| --- | --- |
| 중심 활동 | LLM 설명과 컨텍스트 설명을 각각 완성 |
| 화면·조작 | 활동별 빈칸 4개·후보 8개; 활동 1 완료 뒤 활동 2 |
| 순서 | LLM 설명·예제·빈칸 → 해설 → 컨텍스트 설명·예제·빈칸 → 해설 |
| 제출 | 각 활동의 네 단어 배치, 총 여덟 빈칸 |
| AI 사용 | 사전 작성 설명·예제, LLM 호출 없음 |

**상황**: 글을 만드는 AI와 대화하려면 무엇을 알아야 할지 나래가 설명합니다.

**추가 대사 초안**:

- 나래: “먼저 대규모 언어모델을 알아볼게요. 다음에는 대화에 제공하는 맥락, 컨텍스트를 살펴봅시다.”
- 고디: “우리가 알려주지 않은 축제 사정까지 저절로 아는 건 아니겠네.”

**활동 A**: LLM 설명문의 핵심 단어 4개를 후보 8개에서 골라 배치합니다. 설명은 언어 패턴을 학습하고 입력에 따라 텍스트를 생성하는 역할과, 자연스러움이 정확성을 보장하지 않는다는 점을 다룹니다. 정확한 설명문·단어·정답은 미정입니다.

**활동 B**: 컨텍스트 설명문의 핵심 단어 4개를 별도의 후보 8개에서 골라 배치합니다. 작업 목적·자료·조건·관련 대화 등 응답에 필요한 맥락을 설명합니다. 이전 대화를 무제한 기억한다거나 모든 정보가 항상 반영된다고 설명하지 않습니다. 정확한 설명문·단어·정답은 미정입니다.

각 활동의 해설과 재시도는 분리합니다. 이미 완료한 첫 활동을 두 번째 활동 오답 때문에 반복시키지 않는 방향이며 재접속 저장 범위는 별도 결정합니다.

## 1-4 — LLM 대화의 요령

**유형: 이지선다(3문항)**

### 진행 형태

| 항목 | 방식 |
| --- | --- |
| 중심 활동 | 제시된 업무 상황에 맞는 대화·검증 방식 선택 |
| 화면·조작 | 상황 설명, 두 선택지 버튼, 확인·해설 |
| 순서 | 상황 읽기 → 선택 → 이유 해설·수정 → 다음 문항 |
| 제출 | 세 상황의 선택 |
| AI 사용 | 고정 문제·해설, LLM 호출 없음 |

**추가 대사 초안**:

- 나래: “이번에는 상황에 맞는 대화 방법을 골라 보세요.”
- 고디: “항상 길게 말하거나 무조건 계획부터 세우라는 뜻은 아니구나.”

| 문항 상황 | 비교하는 두 방식 | 정답 방향과 해설 |
| --- | --- | --- |
| 축제 안내문에 대상·일시·장소·형식이 필요함 | 필요한 정보를 생략한 단어 나열 / 작업에 필요한 맥락을 제공 | 필요한 맥락 제공. 글의 길이 자체가 기준은 아님 |
| 여러 자료와 조건을 다루는 복합 업무 | 곧바로 최종 답만 요청 / 계획·단계를 확인하고 실행 | 해당 복합 상황에서는 계획 확인 후 실행. 단순 요청까지 계획을 의무화하지 않음 |
| 사실·수치가 담긴 답변을 받음 | 그대로 신뢰 / 원자료·근거로 다시 확인 | 원자료·근거 확인. AI에게 같은 질문을 반복하는 것만으로 검증 완료가 되지 않음 |

실제 질문 문장·선택지 전문·상황 자료는 미정입니다. 정답을 고른 경우에도 그 상황에서 적절한 이유와 적용 범위를 설명합니다.

## 1-5 — AI로 해결하기 적합한 문제

**유형: 사례 선택형 + 이유 서술형(내부 LLM API 채점)**

### 진행 형태

| 항목 | 방식 |
| --- | --- |
| 중심 활동 | 사례별 적합한 도구를 판단하고 이유 설명 |
| 화면·조작 | 사례·조건 카드, 선택 버튼, 이유 입력창, 피드백·수정 |
| 순서 | 사례 비교 → AI 활용 여부 선택 → 이유 작성 → API 평가·피드백 → 필요한 수정 |
| 제출 | 선택 사례·선택 도구와 이유 |
| AI 사용 | 내부망 LLM API로 선택·이유 평가; 연결·평가 구현 전 |

**상황**: 나래가 축제 업무를 맡기기 전에 어떤 문제에 AI가 도움이 될지 묻습니다.

**추가 대사 초안**:

- 나래: “반복되는 일이 많아요. 그런데 모든 일을 AI에 맡기는 것이 좋을까요? 사례를 고르고 이유를 알려 주세요.”
- 고디: “정해진 계산인지, 글을 읽고 정리하는 일인지부터 보자.”

**사례 작성 기준**: 자연어·비정형 자료의 해석이나 초안 작성이 필요한 사례와, 명확한 규칙·합계를 계산 도구나 일반 자동화로 충분히 처리하는 사례를 함께 제시합니다. 반복·규칙·매뉴얼만으로 AI가 더 적합하다고 판정하지 않습니다. 실제 사례 목록과 수는 미정입니다.

**판정 방향**: 사용자는 AI를 고른 이유 또는 일반 도구가 더 적합한 이유를 설명합니다. 사례 조건·자료·도구 기능과 이유가 연결되는지, 검토와 한계를 고려했는지 평가합니다. AI를 사용하지 않는 타당한 선택과 동등한 표현을 인정합니다.

**API 채점 설계**: 내부 API를 사용한다는 방향은 승인되었습니다. 평가 기준 전문·점수·통과 조건·재검토 절차·일관성 확인·인증과 호출 명세는 미정입니다. API 장애를 학습자 오답으로 처리하지 않고 작성한 이유를 유지하는 방향으로 설계합니다. API 점수 하나만으로 최종 통과를 확정하는 규칙을 임의로 추가하지 않습니다.

**피드백 초안**: “선택한 도구가 이 자료를 어떻게 처리하는지 이유에 연결해 볼까요?” 완성 답안을 먼저 제시해 그대로 복사하도록 하지 않습니다.

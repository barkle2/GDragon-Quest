# 월드 3 상세 시나리오 — 지혜의 도서관

## 목표·이야기·공통 방식

2026-10-16: 사용자 제공 ‘AI와 함께 만드는 축제 안내문’ 커리큘럼을 반영해 월드 3을 개정했습니다. 나와 고디는 왕국 도서관인 **지혜의 도서관**에서 AI와 편집 도구를 활용해 축제 안내문 한 종을 완성합니다. 앞면에는 축제 일정, 뒷면에는 장터 지도를 담습니다.

핵심 목표는 AI에게 그림을 요청하는 데서 나아가 목적 정의 → 구성 설계 → 초안 생성 → 부분 수정 → 최종 검증을 수행하는 것입니다. 다섯 스테이지는 서로 독립된 그림 과제가 아니라, 앞 단계 산출물을 다음 단계 입력으로 사용하는 하나의 제작 과정입니다.

| 스테이지 | 활동 | 다음 단계로 넘길 산출물 | 권장 시간 |
| --- | --- | --- | --- |
| 3-1 | 목적과 요구사항 정의 | 제작 요구사항 5개 이상 | 5분 |
| 3-2 | 앞면·뒷면 구성 설계 | 양면 와이어프레임과 영역별 설계 | 10분 |
| 3-3 | 앞면 이미지 초안 생성·비교 | 초안 2개, 선택안과 선택 이유 | 15분 |
| 3-4 | 문제를 찾아 부분 수정 | 수정 전·후 이미지, 개선 기록 3개 | 15분 |
| 3-5 | 지도 결합·편집·최종 검증 | 앞면·뒷면으로 구성된 안내문 1종과 검증 기록 | 15분 |

총 60분은 초보 직원 실습을 위한 운영 권장안입니다. 게임 내 제한 시간이나 실제 측정한 소요 시간이 아닙니다. 힌트·수정·재도전에 감점은 없습니다. 초보자용 기본 구성은 앞면을 직접 생성하고 뒷면은 미리 제공한 지도 시안을 수정·결합하는 방식입니다.

준비물은 이미지 생성 AI, PowerPoint 또는 유사 편집 도구, 실습용 가상 축제 정보입니다. 게임 내 생성·부분 편집·문서 편집·내보내기 기능의 구현 방식은 미정입니다. 아래는 제작할 시나리오이며 실제 이미지나 PDF를 이번에 생성한 것은 아닙니다. 첫 시제품의 월드 1 구현 범위는 유지합니다.

## 등장인물과 도입 — 물감 묻은 부탁

새 화가의 이름은 **채린**으로 정합니다. 성인 공작새 수인 화가로, 청록색 깃털과 접은 부채꼬리, 물감 묻은 앞치마, 여러 굵기의 붓을 지닌 외형을 제안합니다. 그림을 좋아하고 표현이 풍부하지만 일이 몰리면 설명을 서두르는 인물입니다. 종족·외형은 제작 후보이며 이미지 자산은 아직 없습니다.

나와 고디는 사람들에게 나눠 줄 안내문을 만들어 달라는 부탁을 받고, 인쇄기가 있는 지혜의 도서관으로 향합니다. 인쇄실 옆 작업대에는 미완성 축제 장식과 그림들이 쌓여 있고, 채린이 붓을 든 채 두 사람을 맞습니다.

- 나: “여기가 안내문을 인쇄할 수 있다는 지혜의 도서관이구나.”
- 고디: “먼저 어떤 안내문이 필요한지 물어보자.”
- 채린: “왕국지원단에서 오셨군요! 마침 잘됐어요. 축제 장식에 표지판까지, 그려야 할 게 너무 많거든요.”
- 채린: “사람들에게 나눠 줄 축제 안내문은 두 분이 좀 만들어 주실래요? 앞면에는 축제 일정을, 뒷면에는 장터 지도를 넣어야 해요.”
- 나: “그림도 그리고 일정도 정리해야 하네. AI와 함께 만들어 보면 어떨까?”
- 채린: “좋아요! 확정 일정표와 장터 배치도는 여기 있어요. 어린이부터 어르신까지 편하게 읽을 수 있으면 좋겠어요.”
- 고디: “바로 그리기 전에, 필요한 것부터 정리해 보자.”

### 공통 자료 서랍

- 축제 확정 일정표: 축제명, 날짜·요일, 행사 시간·이름·장소, 안내사항을 담을 제작용 가상 자료.
- 장터 확정 배치도: 부스번호와 가게명, 출입구·통로·편의시설 위치를 담을 제작용 가상 자료.
- 뒷면 지도 시안: 배치도에 근거한 기본 지도. 3-2의 설계와 3-5의 수정·결합에 사용합니다.
- 채린의 제작 조건 메모: A4 세로형 양면, 다양한 연령의 주민 대상, 밝고 따뜻한 분위기, 일정과 길 찾기 정보 우선.

구체적인 일정·가게명·좌표는 후속 자료 제작 시 확정합니다. 참고자료의 가을 축제·요일별 행사 예시를 기존 봄맞이축제의 실제 설정으로 옮기지 않습니다. 월드 2에서 추천한 가게를 배치도에 넣으려면 최종 선정·부스 배정이 확정된 자료를 별도로 제공해야 합니다. 추천 결과만으로 확정 가게를 만들지 않습니다.

## 3-1 — 무엇을 위한 안내문일까?

**유형: 질문 선택형 대화 + 자유 입력 요청형 + 요구사항 편집형**

### 목표와 시작 대사

용도·대상·내용·규격·분위기를 구체화한 제작 요구사항을 5개 이상 작성합니다.

- 나: “예쁜 안내문이면 되는 걸까?”
- 채린: “예쁘면 좋지만, 주민들이 일정을 읽고 가게를 찾아갈 수 있어야 해요.”
- 고디: “누가 어디서 어떻게 쓸지부터 정하면 좋겠네.”

### 진행과 요청 예시

채린에게 대상·담을 정보·인쇄 크기·분위기를 질문하고, 답변 메모와 공통 자료를 바탕으로 AI에 요구사항 정리를 요청합니다. NPC 답변은 제작 조건에 따른 사전 작성 대화이며 자유 질문 이해 기능을 전제로 하지 않습니다.

> 봄맞이축제에서 주민들에게 나눠 줄 안내문을 만들려고 해. 앞면은 축제 일정, 뒷면은 장터 지도이고 A4 세로형 양면 인쇄물이야. 어린이부터 어르신까지 읽기 쉽게 만들고 싶어. 제공한 자료와 채린의 설명을 바탕으로 목적, 대상, 내용, 크기, 디자인 관점에서 제작 요구사항을 정리해줘. 아직 정해지지 않은 내용은 질문으로 남겨줘.

사용자는 AI의 정리에서 잘못된 가정·누락을 고치고 요구사항 문서를 완성합니다. ‘목적·대상·내용·규격·분위기’ 다섯 관점을 포함해야 하며 같은 조건을 다섯 번 바꿔 쓴 것을 충분한 요구사항으로 보지 않습니다.

### 산출물·완료와 전환

- 제작 요구사항 5개 이상과 추가 확인 사항. 예: 주민의 일정 확인과 길 찾기, 다양한 연령, 앞면 일정·뒷면 지도, A4 세로형 양면, 밝은 분위기와 읽기 쉬운 대비.
- 요청 문장의 일치가 아니라 제작에 적용할 수 있는 구체성을 확인합니다. 정해지지 않은 날짜·시설을 임의로 추가하면 자료를 다시 보도록 안내합니다.
- 고디: “무엇을 만들어야 할지 분명해졌어. 이제 종이의 어느 곳에 무엇을 놓을지 정해 보자!”

## 3-2 — 앞면과 뒷면의 자리 잡기

**유형: 레이아웃 설계형 + 자유 입력 요청형**

### 목표와 시작 대사

3-1의 요구사항을 사용해 앞면·뒷면을 각각 3~5개 영역으로 나누고, 위치·크기·내용·색상·우선순위를 정합니다.

- 채린: “일정과 지도가 장식보다 먼저 보여야 해요.”
- 나: “그림을 생성하기 전에 네모 상자로 배치부터 그려 보자.”

### 진행과 요청 예시

> 앞서 정리한 제작 요구사항으로 안내문 양면을 설계해줘. 각 면을 3~5개 영역으로 나누고 위치, 크기, 들어갈 내용, 색상, 우선순위를 적어줘. 앞면은 축제 일정, 뒷면은 장터 지도가 가장 눈에 띄도록 간단한 와이어프레임으로 제안해줘. 정확한 글자는 나중에 편집할 수 있도록 글자 영역과 그림 영역을 구분해줘.

| 면 | 영역 구성 예시 | 확인할 점 |
| --- | --- | --- |
| 앞면 | 상단 제목 / 중앙 일정표 / 하단 안내·편의시설 | 일정표에 가장 넓은 공간, 제목과 본문 위계, 글자와 배경 구분 |
| 뒷면 | 상단 지도 제목 / 중앙 지도 / 하단 부스 목록·범례 | 통로·출입구가 보이는 지도, 번호와 가게명 대응, 시설 기호 설명 |

사용자는 와이어프레임의 상자와 내용을 조정하고 각 영역의 대략적인 크기나 면적 비율을 남깁니다. 지도는 제공된 배치도를 기준으로 하며 보기 좋게 만들려고 부스나 통로의 실제 관계를 바꾸지 않습니다. 양면의 공통 색상·글씨체·일러스트 방향도 정합니다.

### 산출물·완료와 전환

- 양면 와이어프레임과 영역별 설계표. 앞 단계 요구사항이 어느 영역에 반영됐는지 확인합니다.
- ‘제목은 크게’만 적은 경우 일정·안내정보가 들어갈 공간도 정하도록 돕습니다. 배치가 다르더라도 정보 우선순위와 가독성을 충족하면 인정합니다.
- 채린: “이 설계라면 일정도 지도도 찾기 쉽겠어요. 앞면 시안을 만들어 볼까요?”

## 3-3 — 같은 설계로 두 가지 초안 만들기

**유형: 이미지 생성 요청형 + 이미지 비교형**

### 목표와 시작 대사

3-1 요구사항과 3-2 설계에 따라 앞면 이미지 초안 2개를 만들고, 제작 목적에 더 맞는 안을 선택합니다.

- 고디: “같은 조건으로 다시 만들어도 결과가 달라질 수 있어. 두 안을 비교해 보자.”

### 진행과 요청 예시

> 첨부한 요구사항과 앞면 레이아웃 설계를 바탕으로 A4 세로형 축제 안내문 앞면 시안을 만들어줘. 밝고 따뜻한 파스텔 색상과 둥글고 부드러운 3D 일러스트 분위기를 사용해줘. 제목은 상단, 제공한 일정은 중앙, 안내·편의시설은 하단에 두고 글자와 그림을 명확하게 구분해줘. 일정표의 가독성을 우선하고, 자료에 없는 행사나 시설은 추가하지 마.

같은 요구사항·설계·요청 조건으로 한 번 더 생성합니다. 결과 A와 B를 함께 보며 일정표 크기, 영역 배치, 장식의 간섭, 색 대비, 편집할 글자 공간을 비교합니다. 같은 조건이 같은 이미지를 보장하지는 않습니다.

| 비교 항목 | 학습자가 남길 기록 |
| --- | --- |
| 요구사항 반영 | 용도·대상·규격·분위기가 어떻게 드러나는가 |
| 구성 반영 | 설계한 제목·일정·안내 영역이 유지됐는가 |
| 읽기 편의 | 더 잘 읽히는 부분과 편집이 필요한 부분은 무엇인가 |
| 선택 이유 | 어떤 안이 안내 목적에 더 적합하며 그 이유는 무엇인가 |

생성된 글자·숫자가 그럴듯해도 확정 정보로 믿지 않습니다. 잘못된 문자·표는 수정 목록에 남깁니다. 정확한 글자를 별도 편집 도구로 넣을 계획도 허용합니다. 이미지가 정확한 A4 픽셀 규격을 제공하지 않으면 최종 편집 문서에서 A4 규격으로 맞춥니다.

### 산출물·완료와 전환

- 앞면 초안 A·B, 선택한 초안, 비교·선택 이유, 개선할 부분 목록.
- ‘더 예뻐서’만 적기보다 일정이 잘 보이는 위치 등 구체적인 근거를 남깁니다. 두 안 모두 부족하면 더 나은 기반을 골라 수정할 수 있습니다.
- 나: “이 안은 일정이 잘 보이지만, 아이콘과 여백은 조금 고치면 좋겠어.”

## 3-4 — 잘된 부분은 살리고 필요한 곳 고치기

**유형: 부분 이미지 편집 요청형 + 수정 전후 비교형**

### 목표와 시작 대사

3-3에서 선택한 초안의 개선점 3개를 찾고, 각 문제에 대해 수정 위치·바꿀 내용·유지할 요소를 구체적으로 요청합니다.

- 채린: “전체 분위기는 마음에 들어요. 그런데 주민들이 읽는 데 불편한 곳은 없을까요?”
- 고디: “바꿀 곳과 유지할 곳을 나눠서 부탁해 보자.”

### 진행과 요청 예시

선택한 이미지를 편집 대상으로 지정하고, 발견한 문제를 표시하거나 해당 영역을 설명합니다. 세 요청을 순서대로 실행하거나 한 요청에 세 부분을 구분해 전달할 수 있습니다.

> 선택한 앞면 시안에서 중앙 일정표를 더 크게 만들어줘. 일정 구분 색은 서로 알아보기 쉽게 바꾸되 글자 대비를 유지해줘. 하단 편의시설 아이콘은 단순한 모양으로 정리해줘. 제목과 전체 일러스트 분위기는 최대한 유지하고, 요청하지 않은 내용과 일정 정보는 바꾸지 마.

위 세 항목은 예시이며 실제 초안의 문제에 맞춰 수정합니다. 요일별 색 구분은 확정 일정에 요일 구분이 있을 때 사용하고, 색상만으로 구분하지 않도록 요일·행사 이름도 표시합니다.

| 개선 기록 | 작성 내용 |
| --- | --- |
| 문제와 위치 | 어느 부분이 왜 불편한가 |
| 수정 지시 | 크기·색·모양·간격 등을 어떻게 바꿀 것인가 |
| 유지 조건 | 제목·스타일·다른 영역 등 무엇을 보존할 것인가 |
| 전후 확인 | 의도한 개선 여부와 예상 밖 변경, 후속 조치 |

요청하지 않은 영역도 바뀔 수 있으므로 수정 후 앞면 전체를 비교합니다. 일정 내용이 달라졌다면 원문에 맞춰 복구하고 다시 확인합니다. 문자·표 수정이 이미지 편집으로 안정적으로 되지 않으면 3-5의 편집 도구 작업으로 분리합니다.

### 산출물·완료와 전환

- 수정 전·후 이미지와 개선 기록 3개, 남은 편집 사항.
- 수정 횟수보다 문제 진단과 구체적인 지시, 전후 확인을 평가합니다. 초안에 불필요한 오류를 넣지 않으며 문제가 적으면 여백·대비 등의 개선 가능성을 살핍니다. 불필요한 변경을 강제하지 않고 유지가 적절한 항목은 이유와 확인 기록으로 인정합니다.
- 채린: “읽기 훨씬 편해졌네요. 이제 뒷면 지도까지 맞춰서 인쇄할 준비를 해 봐요!”

## 3-5 — 양면 안내문 완성하고 인쇄 전 확인하기

**유형: 이미지 결합·문서 편집형 + 원자료 대조형**

### 목표와 시작 대사

수정한 앞면과 제공된 뒷면 지도 시안을 하나의 양면 안내문으로 완성하고, 디자인 통일성·정보 정확성·인쇄 크기의 가독성을 검증합니다.

- 나: “앞면은 준비됐어. 뒷면 지도도 같은 안내문처럼 보이게 맞추자.”
- 채린: “인쇄하면 잘못된 정보가 그대로 나눠지니까 마지막 확인도 부탁해요.”

### 1단계 — 뒷면을 맞추고 양면 결합하기

3-2의 뒷면 설계에 맞춰 지도 시안의 색상·범례·제목을 편집합니다. 앞면과 색상·글씨체·일러스트 분위기를 맞추되 부스 위치·통로·출입구 등 확정 배치 관계를 보존합니다. 새 지도를 처음부터 생성하는 활동은 기본 60분 구성에 추가하지 않습니다.

이미지 생성만으로 정확히 반영하기 어려운 제목·일정표·부스번호·가게명·범례는 편집 도구의 텍스트·표·도형으로 배치합니다. 잘못된 기존 글자는 제거하거나 충분히 가린 뒤 교체해 중복 노출되지 않게 합니다. 한 안내문의 앞면과 뒷면을 각각 페이지로 구성합니다.

참고 요청 예시:

> 앞면과 뒷면을 비교해서 색상, 글씨체, 일러스트 분위기가 일관되는지 점검해줘. 확정 일정표와 배치도를 기준으로 날짜·요일·시간·장소·부스번호·가게명·편의시설을 확인할 체크리스트를 만들어줘. 이미지에서 수정할 부분과 별도 편집 도구의 글자·표로 처리할 부분도 구분해줘.

### 2단계 — 실제 내용과 인쇄 크기 검증하기

| 점검 범주 | 학습자가 수행할 확인 |
| --- | --- |
| 일정 정확성 | 확정 자료와 축제명·날짜·요일·시간·행사·장소를 항목별 대조 |
| 지도 정확성 | 부스번호와 가게명 대응, 위치 관계·통로·출입구·시설·범례를 배치도와 대조 |
| 양면 통일성 | 공통 색·글씨체·그림 분위기와 앞뒤 정보의 일치 확인 |
| 가독성 | A4 실제 크기 미리보기 또는 시험 인쇄에서 글자·표·지도 번호·대비·여백 확인 |
| 파일 규격 | A4 세로형, 앞면·뒷면 2페이지의 순서, 잘림·누락·이미지 선명도 확인 |

AI의 점검 제안만으로 완료하지 않습니다. 학습자는 원자료의 해당 항목과 최종 편집본을 직접 비교하고 일치·수정·확인 필요를 기록합니다. 오류를 고친 뒤 내보낸 파일을 다시 열어 수정 반영과 페이지 구성을 확인합니다. 실제 인쇄를 하지 않았다면 화면 검증과 시험 인쇄를 구분해 기록합니다. 지도에서 출입구부터 특정 가게까지 길을 따라가 보며 길 찾기 가능성도 확인합니다.

### 산출물·완료 조건

- A4 앞면·뒷면 2페이지 PDF 1개 또는 앞면·뒷면을 구분한 이미지 파일 묶음. 파일 묶음도 최종 안내문 한 종으로 취급합니다.
- 편집 가능한 원본과 최종 검증 기록. 편집 원본의 형식·보관 방식은 구현 시 정합니다.
- 필수 일정과 지도 정보에 누락·불일치가 없고, 실제 크기에서 읽을 수 있으며 양면 구성이 맞아야 인쇄 준비 완료로 표시합니다.
- 확인되지 않은 정보가 남으면 인쇄 대기로 두고 채린에게 무엇을 확인해야 하는지 전달합니다. 연습 제출과 인쇄 준비 완료는 구분합니다.

## 월드 3 마무리 — 인쇄기에 올릴 한 장

검증한 안내문 앞면과 뒷면을 채린에게 보여줍니다. 인쇄 준비 조건을 충족한 경우 채린이 시험 인쇄를 확인하는 장면으로 연결합니다. 확인 대기 항목이 있다면 인쇄를 보류하는 대사로 분기합니다.

- 나: “앞면에는 축제 일정을, 뒷면에는 장터 지도를 넣었어요. 날짜와 부스번호도 원자료와 맞춰 확인했어요.”
- 채린: “정말 고마워요! 주민들이 일정을 보고 가게도 쉽게 찾아갈 수 있겠어요.”
- 채린: “처음부터 무작정 그린 게 아니라, 구성을 정하고 필요한 부분을 고쳐서 완성했군요. AI와 함께 만드는 솜씨가 멋져요!”
- 고디: “그림을 만드는 것만큼, 어디에 쓸지 정하고 결과를 확인하는 것도 중요했어.”
- 확인 대기 분기 — 채린: “이 항목만 확인하고 인쇄하면 되겠네요. 필요한 내용을 따로 적어 줘서 고마워요.”

채린이 안내문과 제작 기록을 받아 들고, 나와 고디는 다음 여정인 분주한 항구도시로 향합니다. 확인 대기 상태에서는 인쇄 완료 연출을 재생하지 않습니다.

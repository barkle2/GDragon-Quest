# 월드 4 상세 시나리오 — 분주한 항구도시

[전체 시나리오](시나리오.md) · [등장인물](등장인물.md) · [수행형 활동과 검토](수행형활동과검토.md)

## 목표·이야기·공통 방식

승인한 방향은 여러 자료로 AI 문서·요약·답변·보고를 직접 완성하는 것입니다. 구체적 자료·판정·대사는 검토 초안입니다. 실제 업무 절차나 외부 메시지 발송을 실행하지 않습니다. 첫 시제품은 월드 1입니다.

해루(수달 운영 담당), 소담(인간 상담 담당), 바루(바다코끼리 상인), 피오(어린 주민)가 등장합니다. 부탁·설명·부분 예제 후 자료 선택→직접 AI 요청→원문 대응·수치 확인→편집→후속 부탁을 수행합니다. 산출물·판단 근거와 변화 적용을 확인하며 공통 검증·지원 규칙은 수행형 활동 문서를 따릅니다.

## 4-1 — 전달할 메시지 완성하기

**유형: 직접 입력 대화형(LLM)** / 보조: 문서 편집형·근거 연결형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 자료 선택·직접 AI 요청·메시지 편집 |
| 화면·조작 | 자료 서랍·대화·근거 연결·메시지 입력 |
| 순서 | 대상·자료 확인 → 초안 요청 → 사실 대조·수정 → 위치 변경 적용 |
| 제출 | 메시지·근거·수정 이유 |
| AI 사용 | 실제 LLM 초안 후보, 연결은 미구현 |

**목표**: 서로 다른 자료에서 필요한 정보를 골라 대상에게 맞는 메시지를 만듭니다.

- 피오: “친구가 처음 와요. 어디서 만나고 무엇을 해야 하는지 알려 주세요.” 고드래곤: “친구가 따라할 수 있는 안내를 만들어요.”
- 자료: 이번 장터 달맞이날 오전10시·중앙 광장, 만남은 오전9시30분 동쪽 부두 안내소, 초대장 확인 후 함께 이동. 지난 장터 서쪽 안내소 자료도 제공합니다.
- 설명문: “행사 시간과 만남 시간을 구분하고 필요한 행동을 순서대로 전달합니다.” 예제는 자료 항목 하나의 근거 연결만 보여줍니다.

**수행**: 자료·대상을 확인하고 자신의 요청으로 AI 초안을 만듭니다. 초안에서 만남·행사·이동 정보의 근거를 연결한 뒤 최종 메시지를 편집합니다.

**산출물·완료 후보**: 오전9시30분 동쪽 안내소·초대장 확인·10시 중앙 광장이 정확한 메시지, 선택 자료와 수정 이유. 다른 문체·동등 표현을 허용합니다.

**후속 부탁**: 만남 위치가 서쪽 부두 안내소로 바뀐 새 공지를 제공합니다. 오래된 서쪽 자료를 우연히 맞춘 것과 새 근거를 사용한 것을 구분하고 변경 이유를 남깁니다.

힌트 “행사와 만남이 같은 시간인가요?” 수정 “친구가 어디서 먼저 만나는지 빠졌어요.” 완료: 피오 “이 안내를 따라가면 되겠어요!”

## 4-2 — 여러 부탁을 요약하기

**유형: 직접 입력 대화형(LLM)** / 보조: 표 편집형·근거 연결형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 복수 자료 요약·표 편집·원문 대응 |
| 화면·조작 | 부탁 묶음·AI 대화·요약표·미확인 목록 |
| 순서 | 요약 요청 → 조건 검토 → 표·확인 목록 완성 → 정정본 반영 |
| 제출 | 요청별 요약·근거·미정 상태·정정 이유 |
| AI 사용 | 실제 텍스트 요약 후보, 파일 분석 기능은 가정하지 않음 |

**목표**: 복수 문서의 필수 사실을 보존하고 불확실한 내용을 구분합니다.

- 소담: “세 부탁을 담당자가 볼 수 있게 정리해 주세요.”
- 자료: A 바루 빵12상자·달맞이날9시까지 동쪽 창고·도착 전 연락. B 꽃8묶음·10시 중앙 광장·수령 담당 미정. C 물병 수량 확인 중·서쪽 창고·기한 미정.
- 설명문: “짧게 요약하되 요청별 수량·단위·기한·장소·미정 상태를 보존합니다.” 예제는 한 필드만 옮겨 보여줍니다.

**수행**: AI에 요약을 요청하고 요청별 요약표를 완성합니다. 각 행과 원문을 연결하고 빠진 조건을 수정합니다. 맡길 수 없는 확정은 담당자 확인 목록으로 남깁니다.

**산출물·완료 후보**: 세 부탁의 요약표·미확인 목록·근거. 자료에 없는 원인이나 수량을 만들지 않으며 겹치는 정보를 무리하게 합치지 않습니다.

**후속 부탁**: B는 꽃8묶음에서6묶음으로 정정됐다는 자료를 줍니다. 이전 요청과 중복 행으로 더하지 않고 정정 근거를 남겨 수정합니다.

힌트 “미정인 값도 중요한 정보예요.” 수정 “연락 조건이 요약에서 사라졌어요.” 완료: 소담 “담당자가 확인할 항목까지 알 수 있네요.”

## 4-3 — 자료를 집계하고 설명하기

**유형: 표 편집형·계산 입력형** / 보조: 직접 입력 대화형(LLM)·서술형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | AI 자료 구조화·계산 확인·집계 설명 |
| 화면·조작 | 원자료·AI 표·계산식·집계/설명 편집 |
| 순서 | 표 요청 → 단위·품목 확인 → 계산 → 미정 구분 → 추가 확정 집계 |
| 제출 | 표·계산 근거·합계와 제한 설명 |
| AI 사용 | 구조화·설명 보조, 산술 확인은 계산 도구 |

**목표**: AI로 자료를 구조화하고 계산 도구로 집계·해석을 검증합니다.

- 바루: “품목과 단위가 섞인 기록에서 빵 수량을 확인해 주세요.”
- 자료: 동쪽 빵3상자·서쪽 빵2상자·상자당10개·별도 빵5개·꽃8묶음·빵 수량 미정1건.
- 설명문: “AI에게 정리를 맡길 수 있지만 산술·범위·누락 처리 기준은 확인합니다.” 예제는 상자당 수량 변환식 한 개입니다.

**수행**: 직접 요청해 표를 만들고 필요한 열·품목을 선택합니다. 계산 도구에 검증 식을 입력합니다. 확인된 빵55개와 미정1건을 분리해 집계표·짧은 설명을 완성합니다.

**산출물·완료 후보**: 원문 대응 표·(3+2)×10+5=55 근거·전체량 미확정 설명. 꽃을 더하거나 미정을0으로 확정하지 않습니다.

**후속 부탁**: 미정 주문이 빵2상자로 확정됐다는 자료를 줍니다. 중복 없이 추가해75개로 갱신합니다. 계산·범위·미정 상태 해소 이유를 남깁니다.

힌트 “계산이 맞아도 전체량이 확정됐나요?” 완료: 바루 “확인된 합계와 남은 기록이 구분됐어요.”

## 4-4 — 근거 있는 보고서 쓰기

**유형: 문서 작성·편집형** / 보조: 직접 입력 대화형(LLM)·근거 연결형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 보고 초안 생성·사실/추정 검토·보고 편집 |
| 화면·조작 | 복수 자료·AI 대화·근거 목록·보고 편집 |
| 순서 | 독자·목적 설정 → 요청 → 수치·근거 검토 → 보고 완성 → 추가 관찰 반영 |
| 제출 | 보고서·근거·수정/유지 이유 |
| AI 사용 | 실제 LLM 초안 후보, 인과 판단은 자료와 대조 |

**목표**: 여러 자료를 바탕으로 사실·추정·제안을 구분한 보고서를 만듭니다.

- 해루: “배송 지연의 현황과 다음 조치를 보고해 주세요.”
- 자료: 배송20건 중5건 지연, 지연5건 중4건 연락처 누락. 주민 메모에는 안내 혼란이 언급됨. 모든 원인은 조사 전. 제안 가능 범위는 작은 연락처 확인 시범.
- 설명문: “현황·근거·미확인 원인·제안을 구분하고 인과관계를 자료 이상으로 단정하지 않습니다.” 예제는 사실 한 문장과 추정 한 문장만 비교합니다.

**수행**: 독자가 운영 담당자임을 확인해 AI 초안을 작성합니다. 근거 위치·비율5/20=25%를 직접 확인하고 수정합니다. 작성 목표·현황·검토 의견·조치 제안의 짧은 보고서를 완성합니다.

**산출물·완료 후보**: 지연25%·연락처 누락의 관찰·원인 미확정·시범 제안, 근거 목록·수정 이유. 문단 순서는 허용 범위 안에서 자유입니다.

**후속 부탁**: 원래 정시15건 중8건에도 연락처 누락이 있었다는 추가 자료를 줍니다. 누락이 지연을 유발했다고 단정한 표현을 재검토하고 추가 조사 필요성을 보고에 반영합니다.

힌트 “지연하지 않은 기록도 볼 필요가 있나요?” 완료: 해루 “추정의 한계까지 읽을 수 있는 보고네요.”

## 4-5 — 접수부터 답변까지

**유형: 직접 입력 대화형(LLM)** / 보조: 질문 선택형 대화·표/문서 편집형·분류형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 복합 부탁 처리·접수표·답변/인계 작성 |
| 화면·조작 | 질문·자료·AI 대화·분류/담당 표·답변 편집 |
| 순서 | 정보 확인 → 접수·답변 초안 → 분류·근거 검토 → 인계/전달 → 후속 회신 갱신 |
| 제출 | ID별 요약·담당·답변·대기 상태 |
| AI 사용 | 실제 LLM 지원 후보, 외부 발송 기능 없음 |

**목표**: 새 부탁 여러 건을 요약·분류·초안·검토·인계로 연결합니다.

- 소담: “이번 묶음은 분류도 필요한 답변도 직접 정해 주세요.” 고드래곤: “답할 수 있는 것과 확인이 필요한 것을 나눠요.”
- 자료: 배송 가능 문의(빵12상자·달맞이날9시 동쪽 창고), 방문 위치 문의(공개 지도), 수량 정정 문의(기존 요청ID와 정정 내용). 담당자 표: 배송 가능은 항구 확인, 위치는 공개 지도, 정정은 해당 주문 원본 확인.
- 설명문: “작업 결과를 다음 단계에 넘길 때 ID와 조건을 유지합니다.” 정답 분류표는 제공하지 않습니다.

**수행**: 필요한 정보를 질문 카드로 보완하고 AI로 접수표·답변 초안을 만듭니다. 사용자가 분류·담당 연결을 수정하고 원본 근거를 확인해 답변 또는 인계 기록을 완성합니다.

**산출물·완료 후보**: 요청ID별 요약·담당·최종 답변·확인 대기. 미확인 배송을 보장하지 않고 정정을 신규 주문으로 중복 처리하지 않습니다.

**후속 부탁**: 배송 가능 회신과 별도 위치 변경을 제공합니다. 해당 건만 갱신해 전달하고 다른 대기 건을 완료로 처리하지 않습니다.

힌트는 요청 시 작업 범주만 제공합니다. 완료: 소담 “여러 부탁이 각 담당자에게 정확히 이어졌어요.” 고드래곤은 공방지구로 연결합니다.

## 후속 검토

실제 API·문서 편집·근거 연결·계산 UI·의미 검증·시간·보상은 미정입니다. 실제 메시지 발송 없이 게임 내 전달을 표현합니다. 플레이 산출물과 새 자료 적용을 확인하기 전 학습 효과를 단정하지 않습니다.

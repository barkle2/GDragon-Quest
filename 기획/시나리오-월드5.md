# 월드 5 상세 시나리오 — 멈춰 선 공방지구

[전체 시나리오](시나리오.md) · [등장인물](등장인물.md) · [수행형 활동과 검토](수행형활동과검토.md)

## 목표·이야기·공통 방식

승인한 방향은 작업 흐름을 구성하고 정상·예외 입력으로 시험해 수정하는 것입니다. 아래 명세·자료·대사·통과 조건은 검토 초안입니다. 실제 자동화 코딩 능력이 아니라 제한된 게임 내 흐름 설계·시험을 다룹니다. 첫 시제품은 월드 1입니다.

탄(멧돼지 기술자), 리아(인간 설계 담당), 누리(작은 돌 골렘)와 주문 취합 흐름을 복구합니다. 누리의 마법 존재 설정과 AI 기능은 구분합니다. 부탁·설명·예제→설계·시험→결과 검토·수정→새 입력 시험→완료로 진행합니다. 공통 도움·검증·API 예외는 수행형 문서를 따릅니다.

**가상 시험 환경 후보**: 텍스트 정리(AI), 명시 필드 확인, ID 중복 확인, 정확한 산술, 조건 분기, 확인 대기, 사람 승인, 게임 내 전달 블록. 사용자가 입력·출력 연결을 정하고 시험 버튼을 누르면 단계별 상태·산출물을 봅니다. 실제 장비나 외부 시스템은 조작하지 않습니다. 블록 실행기·의미 판단·API 기능은 아직 구현하지 않았습니다.

## 5-1 — 반복업무를 흐름으로 만들기

**유형: 흐름 구성·실행형** / 보조: 서술형(입출력 명세·시험 기록)

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 흐름 구성·입출력 정의·실행 시뮬레이션 |
| 화면·조작 | 블록·연결 메뉴·필드 편집·시험 버튼·단계 기록 |
| 순서 | 단계·필드 정의 → 연결 → 정상 시험 → 누락 입력 시험·수정 |
| 제출 | 흐름·명세·시험 기록 |
| AI 사용 | 필요 처리 블록에 적용 후보, 실행기는 별도 미구현 |

**목표**: 작업의 입력·출력·검토 지점을 직접 정의합니다.

- 탄: “주문을 받아 정리하고 전달하는 일을 매번 다시 해요.” 고드래곤: “다음 단계에 무엇을 넘겨야 할까요?”
- 자료: 주문ID·품목·수량·단위·받는 곳이 있는 메모3개. 예제는 수신 블록과 그 출력 하나만 보여줍니다.
- 설명문: “단계 이름뿐 아니라 무엇을 받아 무엇을 내보내는지 정의합니다.”

**수행**: 입력·처리·검토·전달 블록을 배치하고 연결합니다. 필요한 필드를 정하고 각 블록의 출력 양식을 작성합니다. 정상 주문으로 시험해 단계별 기록을 확인합니다.

**산출물·검토**: 흐름도·필드 명세·시험 기록. ID·수량·단위가 다음 단계까지 유지되고 검토 전 최종 전달하지 않아야 합니다. 단 하나의 배열만 정답으로 강제하지 않습니다.

**후속 부탁**: 받는 곳이 빠진 주문을 줍니다. 누락을 인지하고 확인 대기 경로를 만들어 재시험합니다.

힌트 “다음 단계가 필요한 정보가 남아 있나요?” 완료: 탄 “설계한 흐름에서 누락이 드러나네요.”

## 5-2 — AI와 다른 도구 역할 나누기

**유형: 흐름 구성·실행형** / 보조: 비교표 작성형·서술형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 두 처리안 구성·같은 입력 시험·결과 비교 |
| 화면·조작 | 기능표·흐름 편집·실행 기록·비교/이유 입력 |
| 순서 | 역할 배치 → 동일 주문 시험 → 출력·부담 비교 → 입력 형태 변경·재선택 |
| 제출 | 두 처리안·비교 결과·선택 이유 |
| AI 사용 | 실제 추출 후보와 규칙 처리 비교; 성능 수치 임의 생성 금지 |

**목표**: 처리 방식별 결과·검토 부담을 비교합니다.

- 리아: “같은 작업을 다른 방식으로 처리해 보고 고르세요.”
- 가상 기능: 언어 모델=자유 메모의 표 추출, 규칙=필드 누락 확인, 계산=단위 맞춘 합계, 사람=모호한 주문 확인·최종 승인.
- 설명문: “AI를 많이 쓰는 것이 목표가 아닙니다. 처리 결과와 검토 부담을 비교합니다.” 예제는 산술 도구 한 번 사용입니다.

**수행**: 정형 입력은 규칙·계산으로, 자유 메모는 AI 추출 후 검토로 처리하는 두 흐름을 구성합니다. 같은 주문을 넣어 출력·누락·수정 내용을 비교하고 선택 이유를 작성합니다.

**산출물·검토**: 두 처리안·결과 비교·선택 이유. AI 미사용 처리도 적절하면 허용합니다. 근거 없는 정확성·시간 절감 수치를 주장하지 않습니다.

**후속 부탁**: 자유 메모 대신 필드가 갖춰진 주문을 줍니다. 기존 AI 단계를 유지할지 줄일지 시험 후 이유를 갱신합니다.

힌트 “입력 형태가 바뀌면 방법도 달라질까요?” 완료: 리아 “기능과 결과를 보고 역할을 나눴군요.”

## 5-3 — 분석 흐름을 시험하기

**유형: 흐름 구성·실행형** / 보조: 계산 입력형·표 편집형·서술형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 분석 질문·필터·집계·표현·새 입력 시험 |
| 화면·조작 | 질문 입력·자료·흐름·계산·표/막대 표현·해석 편집 |
| 순서 | 질문·범위 정의 → 흐름 시험 → 수치/누락 확인 → 해석 → 다른 주 적용 |
| 제출 | 분석 흐름·결과·해석·재시험 기록 |
| AI 사용 | 설명 초안 보조, 계산·필터는 제한된 도구 후보 |

**목표**: 질문에 맞는 집계·표현을 구성하고 비교 가능성을 확인합니다.

- 리아: “공방별 생산량이 어떻게 달라졌는지 알아봐 주세요.”
- 자료: 같은 주 A완성10개, B14개, B의 다른 주20개, C이번 주 빈칸. 숫자·단위·주차가 표시됩니다.
- 설명문: “분석 목적과 필터·누락 처리·계산·설명의 관계를 확인합니다.” 예제는 주차 필터 한 단계만 보여줍니다.

**수행**: 비교 질문을 직접 쓰고 해당 주 필터·단위 확인·집계·표 또는 간단한 막대 표현·해석의 흐름을 만듭니다. AI에 설명 초안을 요청할 수 있으나 숫자는 계산 결과와 비교합니다.

**산출물·검토**: 해당 주 A10·B14·C확인 대기, B가A보다4개 많다는 제한된 설명과 시험 근거. C를0으로 처리하거나 B의 두 주를 합치면 수정합니다.

**후속 부탁**: 다음 주 A12·B9·C11 자료를 넣습니다. 흐름의 주차 조건을 바꿔 A가B보다3개 많고 세 자료가 접수된 상태를 확인합니다. 이전 설명을 그대로 재사용하지 않습니다.

힌트 “그래프보다 무엇을 비교하는지 보세요.” 완료: 리아 “다른 주 자료에도 흐름을 적용했어요.”

## 5-4 — 실패 입력으로 고쳐보기

**유형: 흐름 시험·수정형** / 보조: 오류 진단 서술형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 실패 주입 시험·원인 진단·흐름 수정 |
| 화면·조작 | 결함 흐름·시험 자료·단계 상태·진단 메모·재실행 |
| 순서 | 중복/누락/실패 시험 → 원인 기록 → 조치 추가 → 재시험 → 정정 입력 처리 |
| 제출 | 원인·전후 흐름·시험 결과·수정 이유 |
| AI 사용 | 실제 API 장애와 시뮬레이션 실패 상태를 구분 |

**목표**: 중복·누락·도구 실패를 실제 시험 입력으로 발견하고 복구합니다.

- 누리: “정상 주문에서는 되는데 같은 주문이 다시 오면 달라져요.”
- 초기 결함 흐름: 모든 행 합산→자동 전달. 시험 자료: ID101 빵12개 두 번, ID102수량 빈칸, 도구 응답 실패 상태.
- 설명문: “잘된 입력만 시험하면 실패 경로를 놓칠 수 있습니다.” 예제는 오류 메시지 읽기만 보여줍니다.

**수행**: 시험을 실행해 어떤 단계·조건에서 실패했는지 진단 메모를 씁니다. ID 중복 처리·누락 대기·실패 재시도/담당 알림을 추가해 같은 시험을 다시 실행합니다.

**산출물·검토**: 실패 원인·수정 흐름·전후 시험 결과. 101은12개 한 번, 102는확인 대기, API실패는최종 전달 금지. 실패를 AI가 정답이라고 말한 것으로 통과시키지 않습니다.

**후속 부탁**: 같은ID의 수량 정정본을 제공합니다. 자료에 표시한 버전 규칙(새 버전 확인 후 교체)을 적용해 새 주문과 구분합니다. 단순 중복 제거로 정정본까지 버리지 않습니다.

힌트 “같은 ID가 같은 내용인지도 보세요.” 완료: 탄 “실패와 정정까지 고려한 흐름이 됐어요.”

## 5-5 — 다른 입력에도 작동하는 취합 흐름

**유형: 흐름 구성·실행형** / 보조: 표 작성형(시험표)·서술형

### 진행 형태

| 항목 | 방식 초안 |
| --- | --- |
| 중심 활동 | 독립 흐름 설계·시험 묶음·예외 검토 |
| 화면·조작 | 명세·블록 구성·시험표·결과·대기 목록 |
| 순서 | 흐름·양식 설계 → 시험 입력 선정 → 실행·수정 → 단위 변경 입력 대응 |
| 제출 | 흐름·시험표·확정 결과·대기 상태 |
| AI 사용 | 필요 단계에 적용 가능, 실제 자동화 시스템 구축은 아님 |

**목표**: 도움을 줄인 새 자료 묶음으로 흐름과 예외를 종합 검증합니다.

- 탄: “이제 시험할 입력도 직접 골라주세요.” 리아: “확인 대기가 어디에 남는지 볼 수 있어야 합니다.”
- 필수 요구: 주문ID·수량·단위·받는 곳, 승인 후 전달, 미확인 값 추측 금지. 제공 자료에 각 시험 기대조건이 정의됩니다.
- 설명문: “정상·누락·중복·정정·도구 실패를 고려해 설계합니다.” 완성 흐름은 제공하지 않습니다.

**수행**: 취합 흐름과 처리 양식을 작성하고 직접 시험 묶음을 구성합니다. AI 추출·규칙·계산·사람 확인을 연결하거나 적절한 일반 처리 대안을 선택합니다. 시험표에 입력·기대 상태·실제 상태·수정 이유를 남깁니다.

**산출물·검토**: 흐름·시험표·확정 결과·대기 목록. 정상은승인 후 전달, 누락은대기, 중복은한 번, 정정은버전 확인 후 반영, 도구실패는보류/재시도 등 명시조건 충족을 확인합니다.

**후속 부탁**: 새로운 공방이 단위가 다른 주문을 보냅니다. 단위 변환 근거가 제공되면 변환·검토하고, 없으면확인 대기로 남겨 허위 합계를 만들지 않습니다.

완료: 누리 “완료한 것과 확인할 것이 분리됐어요.” 고드래곤 “왜 이 흐름을 택했는지 왕국에서 설명해 봐요.”

## 남은 결정

블록·연결·조건의 표현, 제한된 실행기, 실제AI와 고정 시험의 기록 구분, 시험 판정·저장·시간·보상은 미정입니다. 실제 자동화 시스템 구축 역량을 인증하지 않으며 시뮬레이션과 새로운 입력 대응의 학습 효과는 검증 전입니다.

# 월드 1 시제품 구현설계

2026-10-15 · 사용자 승인 범위의 구현 초안입니다. 교육 내용·실제 기관 환경의 검수와 학습 효과 검증은 별도입니다.

## 실행과 구성

- 루트 `index.html`을 브라우저에서 직접 열거나 내부 정적 웹 서버로 제공합니다. 빌드·설치·외부 CDN·폰트·LLM·네트워크 요청이 없습니다.
- `js/content.js`: 대사·문항·후보·정답·힌트·해설. `js/core.js`: 판정·상태 검증·저장. `js/screens.js`: 전체 게임 화면, `js/activities.js`: 문항 출력, `js/game.js`: 전환·조작·복습·효과음. `css/game.css`: 반응형 디자인.
- 기존 마을 배경과 고디·나래 이미지를 분리 배치하며 원본은 수정하지 않습니다.
- 이름 입력 → 인트로 → 월드 선택 → 마을 스테이지 선택 → 각 스테이지 시작 대화 → 순차 해제되는 5개 스테이지 → 엔딩 → 완료 화면입니다. 홈·이어하기·복습을 제공합니다. 미니게임은 비활성 준비 중 표시만 합니다.

## 2026-10-15 시안 기준 화면 재작성

- 기준은 `시안/고디월드-월드선택-v1.png`, `시안/시작의마을-스테이지선택-v1.png`, `시안/시작의마을-대화화면-v1.png`입니다. 풍경 전체 위에 지도 핀·캐릭터·입체 크림 패널·청록 버튼을 HTML/CSS로 겹쳐 배치합니다. 시안 PNG를 화면 한 장으로 붙이지 않습니다.
- `assets/backgrounds/godiworld-map-v2.png`는 지도 시안에서 UI·문자·핀·캐릭터를 제거해 imagegen으로 생성한 1672×940 배경입니다. 기존 원본은 보존합니다.
- 월드 1만 선택 가능하며 다른 5개 월드는 준비 중입니다. 스테이지 처음 진입·복습 시 고디와 나래의 3개 대화를 보여주고, 기존 학습 설명·예제·도전으로 연결합니다. 이미 진행 중인 답안을 열 때는 도입을 강제로 반복하지 않습니다.
- 저장 키와 버전·문항 배열을 유지합니다. 새 대화 위치·효과음 필드가 없는 이전 기록은 기본값으로 보완하고 완료·선택·서술을 보존합니다. 과거 미시작 단계에는 새 도입 대화를 제공합니다.
- 스피커는 로컬 Web Audio의 짧은 효과음 전환입니다. 메뉴에서 수동 저장·전체 화면·홈·초기화가 작동합니다. 외부 음원·통신은 사용하지 않습니다.

## 미정 사항에 대한 시제품 결정

- 이름: 앞뒤 공백 제거, 1~7개 사용자 인식 문자(가능한 경우 Intl.Segmenter), 줄바꿈·제어문자 제외. HTML로 해석하지 않습니다.
- 임의 수식어: 가벼운 허풍 3개 중 하나를 시작할 때 선택해 저장하고 같은 이야기에서 유지합니다.
- 모든 필수 문항을 수정 후 해결하면 완료합니다. 힌트·재도전 감점·제한시간은 없습니다. 별·코인·XP의 새 규칙은 만들지 않고 완료 수와 영역별 복습만 표시합니다.
- 답안·진행 중 활동·설명/도전 화면·정답 해설·인트로/엔딩 대사 위치를 브라우저 localStorage에 저장합니다. 완료한 이전 활동은 뒤 활동 오답으로 초기화하지 않습니다.
- 완료한 스테이지의 복습은 임시 상태로 수행해 기존 완료 기록을 보존합니다. 복습 중 재접속하면 원래 완료 화면으로 돌아가며, 진행 중인 미완료 스테이지의 답안은 그대로 복구합니다.
- 저장 실패 시 이번 창에서 계속 가능함과 재접속 저장 불가를 알립니다. 파일 경로/브라우저/프로필별 저장이며 중앙 이수 기록이 아닙니다. 손상·지원하지 않는 버전은 안내 후 새 상태로 시작합니다. 초기화는 확인 후 진행합니다.
- 1-5는 선택 도구의 적합성을 고정 정답으로 확인하고, 이유는 비어 있지 않은지 확인합니다. 의미 채점 없이 준비된 예시 피드백을 보여주는 ‘시제품용 예시 평가’이며 실제 역량 점수로 표현하지 않습니다.

## 문항 초안

| 활동 | 내용·정답 | 판정·해설 |
| --- | --- | --- |
| 1-1 | AI는 데이터에서 **패턴**을 학습하고 **분류**하거나 앞으로의 값을 **예측**하며 글·그림 등을 **생성**할 수 있다 | 빈칸 4·후보 8. 네 위치의 답 일치. 모든 AI가 모든 기능을 제공하거나 항상 정확한 것은 아님 |
| 1-2 | 문서 범주 나누기→분류, 과거 매출로 다음 달 추정→예측, 안내문 초안·설명으로 그림→생성 | 카드 4개를 세 범주로 배치. 각 동작을 기준으로 설명 |
| 1-3 A | LLM은 많은 **텍스트**의 **패턴**을 학습하고 입력 **맥락**에 따라 **문장**을 생성 | 빈칸 4·후보 8. 자연스러움은 정확성 보장이 아님 |
| 1-3 B | 컨텍스트에는 작업의 **목적**, 참고할 **자료**, 지킬 **조건**, 관련 **대화**가 포함될 수 있음 | 빈칸 4·후보 8. 무제한 기억·자동 내부자료 접근으로 설명하지 않음 |
| 1-4 A | 안내문 목적·대상·일시·장소·형식을 알려주기 | 맥락의 적절성이지 요청 길이 경쟁이 아님 |
| 1-4 B | 여러 자료·조건의 복합 업무는 계획·단계를 확인하고 진행 | 단순 요청까지 계획을 의무화하지 않음 |
| 1-4 C | 사실·수치는 원자료·근거 확인 | AI에게 재질문만 하는 것은 독립 검증이 아님 |
| 1-5 A | 가상 주민 의견을 주제별로 정리→AI 보조 | 원문 대조·누락 확인 필요. 공개 가능한 가상자료임을 명시 |
| 1-5 B | 정해진 가격×수량 합계→계산 도구 | 규칙·수치가 명확한 계산에 일반 도구가 적합 |
| 1-5 C | 주민의 권리·의무에 영향을 주는 최종 결정→담당자 판단 | AI 단독 결정 없이 근거·규정·책임 확인 |

문제 전문·8개 후보·해설은 `js/content.js`에서 실제 구현과 함께 관리합니다. 문서의 굵은 단어가 정답입니다. 후보 위치를 정답 순서로만 배치하지 않습니다. 설명과 예제는 도전 전 제공하고 언제든 무료로 다시 열 수 있습니다.
